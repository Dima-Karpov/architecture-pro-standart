# Цифровая трансформация банка «Стандарт»

Проектная работа третьего спринта курса «Архитектор ПО» (Яндекс Практикум).

Небольшой банк расширяет онлайн-каналы, чтобы привлечь более молодых клиентов. Сейчас клиенты в основном старшего возраста и ходят в отделения. В работе нужно оценить текущие процессы и запланировать изменения.

## О компании

Сайт и интернет-банк есть, ими пользуются редко.

- **Сайт** показывает только маркетинговую информацию.
- **Интернет-банк** проводит платежи и открывает текущие счета (дебетовые карты).
- Сотрудники отделений работают напрямую с **АБС**. Это основная система: учёт операций по счетам и бухгалтерия. Интернет-банк для платежей и открытия текущих счетов ходит в АБС **напрямую в её базу**.
- **Кол-центр** принимает звонки в отдельной системе на платформе подрядчика. Операторы работают по скриптам, которые передают бизнес-представители банка.
- При росте нагрузки банк подключает **партнёрский кол-центр**. Это другая компания и другая система, не подрядчик своего кол-центра. Ставки партнёр готов получать файлами, API-вызовов нет.

Фронт-офис работает с посетителями: отделения, маркетинг, продажи. Бэк-офис ведёт процессы, которых клиент не видит. Бэк-офис депозитов и бэк-офис кредитов **не видят данные друг друга**, поэтому ставки сейчас ходят письмами и Excel.

| Направление | Кто | Сколько |
| --- | --- | --- |
| Сеть отделений | менеджеры фронт-офиса | 50 отделений, 500 человек |
| IT интернет-банка | две команды | 10 в банке + 10 у подрядчика |
| IT АБС | команда внутри банка | 20 человек |
| Депозитные продукты | бэк-офис | 50 человек |
| Кредитные продукты | бэк-офис | 50 человек |
| Кол-центр банка | операторы, платформа подрядчика | 200 операторов, сопровождение подрядчика — 5 человек |
| Партнёрский кол-центр | внешняя команда | 100 человек |
| Цифровая трансформация розницы | заказчик архитектуры | 10 человек |

| Система | Стек | Кто меняет |
| --- | --- | --- |
| Интернет-банк | ASP.NET MVC 4.5, .NET Framework 4.5, MS SQL, монолит. Одна группа серверов в ЦОД и резервный ЦОД | банк сам; ядро — подрядчик |
| АБС | Delphi, Oracle, PL/SQL | банк |
| Кол-центр | React, Java Spring Boot, PostgreSQL, микросервисы | подрядчик; специалисты АБС с Java могут расширять |
| Сайт | PHP, React | банк |
| Кредитный конвейер | Camunda, Oracle, обработчики на Java | подрядчик внедрения и IT банка |
| Кредитный скоринг | Python, Flask, PostgreSQL | IT банка |
| Бюро кредитных историй | внешнее, REST API | вне банка |
| СМС-шлюз | шлюз телеком-оператора | IT банка вместе с оператором |

Кредитный конвейер забирает заявки из АБС **раз в сутки через интеграцию по БД**. Скоринг берёт данные из АБС и бюро.

## Зачем трансформация

Ставки по кредитам и депозитам выгоднее, чем у большинства конкурентов. Руководство хочет начать с этих продуктов. Онлайн слабый: сайт — витрина, интернет-банк — платежи и дебетовые карты. Депозит и накопительный счёт открываются только в отделении, в процессе сидит бэк-офис, мгновенно открыть нельзя.

| Горизонт | Что должно получиться |
| --- | --- |
| **6 месяцев**, MVP | Клиент оставляет заявку на депозит или накопительный счёт в интернет-банке. Заявку по-прежнему обрабатывает бэк-офис. Сюда же входит передача ставок в свой и партнёрский кол-центр |
| **Год** | Клиент сам открывает депозит или накопительный счёт в интернет-банке, без бэк-офиса и без сотрудников банка. В отделении работает только фронт-офис |
| **Год**, кредит | Заявку на кредит можно подать в интернет-банке и на сайте. Если данных достаточно, решение — в течение одного дня. Кредитный онлайн делают в рамках года после MVP |

На сайте в ближайшей перспективе можно оставить заявку на депозит: менеджер кол-центра перезванивает и рассказывает условия. Новый клиент после звонка обязан прийти в отделение: банк не принимает клиента без личной проверки документов.

## Требования

### Депозиты, MVP

**Сайт, новый клиент.** Список доступных депозитов с актуальными ставками. Заявка: телефон и Ф. И. О. Дальше звонит менеджер кол-центра, смотрит заявку у себя и может предложить особые условия. После звонка — визит в отделение. Трафик с сайта шифровать: уходит чувствительная информация.

**Интернет-банк.** Список депозитов с актуальными и персональными ставками. Клиент указывает счёт и сумму и подаёт заявку. Операцию подтверждает СМС-код. СМС уходит после подтверждения ставки и после открытия депозита. Заявку обрабатывает менеджер бэк-офиса и подтверждает условия в АБС.

**Ставки.** Сейчас только в XLS. С файлами работают бэк-офис депозитов и бэк-офис кредитов. Ставки и согласование можно положить в АБС.

### Ставки в кол-центр, тоже MVP

Своих клиентов много, они старше, маркетинговая кампания увеличит звонки. Свой кол-центр консультирует хотя бы по текущим ставкам. Если нагрузку не выдержит — подключают партнёрский. Сотрудники партнёра тоже видят актуальные ставки. Система партнёра внешняя: ставки файлами (в уроке пример — SFTP), API сделать нельзя.

### Кредит, год после MVP

Нефункциональные требования те же, что у депозитов.

- **Сайт.** Предложение открыть кредит по ставке. Полные условия лежат в кредитном конвейере. Заявка: телефон и Ф. И. О. Если заполнены паспортные данные — сразу одобрение или отказ. Клиент новый, скоринг только по общим данным бюро. После заявки — СМС прийти в отделение.
- **Отделение.** Менеджер подаёт заявку через АБС. Если на сайте уже было предварительное одобрение, сотрудник продолжает ту же заявку. Совсем новый клиент — новая заявка.
- **Интернет-банк.** Те же условия, плюс предодобренное предложение. Повторный скоринг упрощённый, если ситуация изменилась. Клиент указывает счёт зачисления, подачу подтверждает СМС-код.
- Предодобренные заявки обрабатывают в тот же рабочий день. Обмен АБС → конвейер по-прежнему раз в сутки, чаще нельзя.
- Клиенту уходит СМС при смене статуса заявки.
- Скоринг в рабочие часы и так нагружен, дополнительными предрасчётами его не грузить.

### Ограничения, от которых зависит архитектура

- Новый стек — только если он совместим с текущими платформами и в банке уже есть экспертиза хотя бы на уровне языка. Базы, которые уже есть: **MS SQL** и **Oracle**.
- Очереди на перспективу — **Kafka**. Текущая платформа интернет-банка с Kafka несовместима.
- Микросервисы интернет-банка допустимы только в рамках открытия депозитов.
- Доработку ядра, включая СМС в ядре, делает подрядчик. Бизнес-функционал команда банка делает сама.
- В новом процессе интернет-банк не ходит в API АБС напрямую. База АБС перегружена, масштабируется только вертикально. Онлайн-заявки на много продуктов могут уронить банк.
- Сервисы — 24/7, доступность 99,9%, в том числе при сбое ЦОД. Нужны горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД. Команда интернет-банка считает это пока невыполнимым: клиентов мало, простой даже на день проблемой не считают.
- Отклик по операциям — миллисекунды. Сейчас часть справочников при платежах грузится больше секунды.
- Интерфейс по дизайн-системе банка. Нужна документация, чтобы систему потом расширять.
- Конвейер и скоринг уже рассчитаны на рост: горизонтальное масштабирование, 24/7.
